# On-demand engineering principles

Read only the principles that change a decision in the current task. Loading every principle on every task is unnecessary.

- [Attack the Premise](principles/principle-attack-the-premise.md): When two or more attempted fixes share a failed assumption.
- [Boundary Discipline](principles/principle-boundary-discipline.md): When parsing CLI, configuration, network, or API input.
- [Build the Lever](principles/principle-build-the-lever.md): For nontrivial repeated work.
- [Encode Lessons in Structure](principles/principle-encode-lessons-in-structure.md): When the same correction appears a second time.
- [Exhaust the Design Space](principles/principle-exhaust-the-design-space.md): For a novel interaction or architectural choice without a precedent.
- [Experience First](principles/principle-experience-first.md): For product, interface, and scope tradeoffs.
- [Fix Root Causes](principles/principle-fix-root-causes.md): When debugging a reported failure.
- [Foundational Thinking](principles/principle-foundational-thinking.md): Before adding logic to a substantial change.
- [Guard the Context Window](principles/principle-guard-the-context-window.md): When large outputs and repeated reads crowd the main context.
- [Laziness Protocol](principles/principle-laziness-protocol.md): When refactoring, sizing a diff, or adding abstractions.
- [Make Operations Idempotent](principles/principle-make-operations-idempotent.md): When designing commands, lifecycles, or loops that may retry after a crash.
- [Migrate Callers, Then Delete Legacy APIs](principles/principle-migrate-callers-then-delete-legacy-apis.md): When changing an internal API.
- [Minimize Reader Load](principles/principle-minimize-reader-load.md): When code is hard to trace.
- [Model the Domain](principles/principle-model-the-domain.md): For stateful logic or repeated branching.
- [Never Block on the Human](principles/principle-never-block-on-the-human.md): When a reversible edit can be resolved with reasonable judgment.
- [Outcome-Oriented Execution](principles/principle-outcome-oriented-execution.md): For a rewrite or migration with explicit phase boundaries.
- [Prove It Works](principles/principle-prove-it-works.md): Before claiming completion.
- [Redesign from First Principles](principles/principle-redesign-from-first-principles.md): When integrating a new requirement into an existing design.
- [Separate Before Serializing Shared State](principles/principle-separate-before-serializing-shared-state.md): When concurrent actors write a file, branch, key, or object.
- [Sequence Work into Verifiable Units](principles/principle-sequence-verifiable-units.md): For multi-step changes and migrations.
- [Subtract Before You Add](principles/principle-subtract-before-you-add.md): When evolving an existing system.
- [Test Behavior, Not Implementation](principles/principle-test-behavior-not-implementation.md): When writing or reviewing a test.
- [Type System Discipline](principles/principle-type-system-discipline.md): When defining types in a typed language.
